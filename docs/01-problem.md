# 01 · 业务需求与痛点

评审维度：业务需求与痛点（15%）。

## 目标用户

一人公司与 2-5 人小团队，做品牌出海或跨境获客，没有内容团队，也没有媒体投放预算。典型画像：独立开发者给自己的 SaaS 获客、硬件品牌做海外众筹预热、工具类产品做 Reddit/X 社区渗透。

这类用户的需求不是「帮我写一篇文章」，而是「让内容供给不断档」。

## 三重痛点

**痛点一：多平台原生形态的适配成本。**

X 要一条一判断的短断言，Reddit 反感营销腔、要长上下文和真实数据，小红书要「我实际做了 X，结果是 Y」的第一人称体，INS 是视觉优先加短文案，Discord 是社区口吻。同一条品牌信息，五个平台是五种写法。人工逐平台改写，一条内容的适配时间经常超过创作本身。

**痛点二：单人产能瓶颈。**

内容获客的效力来自持续供给，不是单条爆款。一人公司的时间被产品、交付、运营切分，留给内容的大块时间极少。没有管道化的生产，内容节奏必然断档；断档两周，平台分发权重和用户心智双双掉水位。

**痛点三：数据回流断裂。**

多数团队发完内容就看一眼播放数。哪些选题方向有效、哪种表达形态转化好、哪个平台值得加仓，这些判断没有数据支撑，内容投资无法优化。数据回流不是报表问题，是选题决策的输入问题。

## 需求的真实性依据

来自本项目研究层的实测数据（采集时间 2026-08，语料库 66 账号 / 198 样本）：

- AI builder 内容需求真实存在且量大：B 站单条 Harness 教学类内容 135.9 万播放；YouTube 同类 Karpathy 深度解析 908 万播放、Claude Code 课程类 236.7 万播放。
- 平台间内容形态差异显著：同一主题在 B 站（长视频 + 密集演示）与 X（短断言串）的成功形态完全不同，印证「适配」是独立工序而非转发。
- 供给端稀缺：高质量、可持续、有真实生产证据的 AI 实践类内容仍是少数，多数账号在 20 条以内断更。

结论：需求侧已被市场验证，瓶颈在供给侧的工程化。这正是 Agent 该干的事。

## 我们解决到什么程度

- 痛点一：五段式文案流水线内置渠道适配段，一个选题产出全平台交付包（见 02 文档）。
- 痛点二：单集人效 3-5.5 小时，多渠道交付包一次成型（见 04 文档）。
- 痛点三：五表 CMS 状态层 + 发布包证据链，发布记录与素材、脚本、成片全量关联（见 02、04 文档）。
