# 03 · Demo 指南

评审维度：产品或网站 Demo（20%）。

## Demo 的构成

三部分，从编排逻辑到可运行代码到真实生产记录：

1. **在线交互演示页**：https://369795172.github.io/brand-goglobal-agents/ （`site/index.html`，单文件零依赖）。可交互运行核心环：选题输入实时驱动提示词组装、平台选择、声纹约束展示、五平台示例草稿、发布门与交付包 manifest。示例草稿按 demo 同一提示词真实生成（GLM-5.2，2026-10-11），口径在页面内标注。
2. **可运行的最小核心环**：`demo/run_demo.py`。输入一个选题，输出五个平台（X / Reddit / 小红书 / INS / Discord）的原生形态文案草稿，声纹约束在提示词层生效。支持 `--dry-run`，无 API key 可完整查看编排。
3. **真实生产记录**：本仓库文档中的全部数据来自生产系统实测（见 04 文档）。
4. **演示视频**（可选补充）：端到端走一遍完整生产流程，如有录制将回填链接。

## 快速开始

```bash
cd demo

# 查看完整编排（不需要任何 key）
python3 run_demo.py --dry-run --topic "为什么你的 AI 助手记不住上下文"

# 真实生成（OpenAI 兼容端点）
export OPENAI_BASE_URL=https://api.example.com/v1
export OPENAI_API_KEY=sk-...
export GGC_MODEL=glm-4.7
python3 run_demo.py --topic "为什么你的 AI 助手记不住上下文"
```

输出落在 `demo/out/<时间戳>/`，每个平台一个文件，外加一份 `package.json` 交付包清单。

## Demo 展示的核心机制

### 1. 一次输入，五种平台原生形态

同一个选题，X 版是三条短断言，Reddit 版是带数据的长上下文帖，小红书版是「我实际做了 X，结果是 Y」体，INS 版是视觉优先短文案，Discord 版是社区公告口吻。差异不是翻译，是重写。

### 2. 声纹约束

每个生成提示携带品牌声纹档案：句法节奏（短断言单独成句）、立场强度（三档置信标注）、类域偏好（系统/架构类比优先，禁文学比喻）、禁用词表（营销腔词汇零容忍）、生成后自检清单。demo 中以简化版生效，生产系统为完整 L1-L7 分层档案。

### 3. 发布门前置

demo 输出的交付包自带发布门检查清单（标题、标签、平台规范、时机、来源标注五项），模拟生产系统中的人工确认点。

## 生产系统对照

demo 是核心环的最小化；生产系统的完整能力对照：

| 能力 | demo | 生产系统 |
|---|---|---|
| 多平台文案适配 | 5 平台 | 7 平台 + 持续扩展 |
| 声纹约束 | 简化版 | L1-L7 完整档案 + 禁用词表 + 自检清单 |
| 编辑审核环 | 无 | 独立审核 Agent 打回机制 |
| 状态管理 | 本地文件 | 飞书五表幂等同步 + 终态保护 |
| 素材与成片管线 | 无 | 814 素材索引 + EDL 审阅链路 |
| 证据链 | 无 | SHA-256 清单 |

## 技术要求

- Python 3.9+，零第三方依赖（标准库实现）。
- dry-run 模式零配置；真实生成需要任意 OpenAI 兼容端点（模型可配，实测用 GLM 系列）。
